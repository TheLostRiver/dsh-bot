# deepseek 自主运营 B 站 · 直播互动

让一个 **DeepSeek 驱动的 AI 账号**，以**观众身份**待在你的直播间里，实时看弹幕、挑值得接的梗回一句，并且用语音把话说出来。

```
你（主播）──推流──> B 站直播间
                        │ 弹幕推送（WebSocket）
                        ▼
                   LiveDanmaku ──> 触发策略（值不值得回？）
                                        │
                                        ▼
                            DeepSeek（弹幕短句 + 语音稿）
                                        │
                        ┌───────────────┴───────────────┐
                        ▼                               ▼
               AI 账号发弹幕（≤20字）           edge-tts 合成语音
                        │                               │
                        ▼                               ▼
                  观众在弹幕区看到               OBS 混音 → 观众听到
                        │
                        ▼
               SQLite（事件/回复/观众画像/配额）
```

---

## 一、先说清楚能力边界

**能做到的：**

| 能力 | 说明 |
|---|---|
| 实时读弹幕 | WebSocket 长连接，断线自动重连 |
| 智能筛选 | 提问必回、被 @ 必回、SC 和上舰插队、刷屏过滤、重复去重 |
| 双通道回复 | 弹幕区发短句（受 20 字限制）+ TTS 语音念完整话 |
| 记忆 | 记住谁常来、回过几次、最近聊了什么 |
| 硬性配额 | 分钟/小时/日三级限流，重启不清零 |
| 无人值守 | 断线重连、异常不崩、Ctrl+C 优雅退出 |
| 离线可测 | `DRY_RUN` 模式跑全流程，不碰真账号 |

**做不到 / 有风险的：**

- **不能让 AI 账号"替主播说话"**。它是观众，不是主播，没有主播权限（置顶、禁言、管理）。
- **不能突破弹幕长度和频率限制**。普通账号弹幕约 20 字、有频率风控，硬来就是禁言。
- **不能保证不被判为机器人**。频繁、模板化的回复会被观众举报，也可能触发平台风控。
- **官方没有给"AI 代运营"开白名单**。这套走的是网页端接口，属于灰色地带，账号风险自负。

> 一句话：**把它当成一个话不多但很会接梗的活跃粉丝，而不是一个 7×24 的运营机器人。**

## 二、5 分钟跑起来

> 想少折腾？直接跳到 **[三、Web 管理后台](#三web-管理后台推荐)** —— 扫码登录，不用手抠 cookie。
> 下面是命令行路线，适合想放进脚本/计划任务的人。

### 1. 装依赖

```powershell
cd D:\DEV\bili-auto
python -m pip install -r requirements.txt
```

### 2. 填配置

```powershell
copy .env.example .env
notepad .env
```

最少要填四项：`BILI_ROOM_ID`、`BILI_SESSDATA`、`BILI_BILI_JCT`、`DEEPSEEK_API_KEY`。

### 3. 自检

```powershell
python scripts/check_env.py
```

它会把依赖、配置、直播间、cookie 有效性、DeepSeek 连通性逐条打出来，全绿再往下走。

### 4. 先干跑一次

```powershell
python scripts/run_live.py --dry-run
```

这一步会真的连上直播间、真的调 DeepSeek，但**不会发弹幕**。日志里能看到 `[DRY-RUN] 本应发弹幕：xxx`，确认语气、长度、节奏都合适。

### 5. 正式开播

```powershell
python scripts/run_live.py
```

## 三、Web 管理后台（推荐）

命令行能用，但手填 cookie 太麻烦。后台把这件事变成「扫码 + 点按钮」：

```powershell
python scripts/run_web.py
# 浏览器打开 http://127.0.0.1:8787
```

只绑定 `127.0.0.1`，局域网访问不到 —— 凭据在本机，别往外开。

### 第一次进后台

1. 点 **「生成二维码」** → 手机 B 站扫码 → 确认时选「**记住我 / 长期**」
   （选 24 小时那张，第二天就得重扫）
2. 右上角显示 `账号：xxx Lv1`，账号风险也会直接标出来
3. 填 **目标直播间房号**（你自己的直播间，不是 AI 账号的）
4. 点 **「启动」**

### 后台是分页的

左侧导航七个页面，各管一摊，别在一页里找：

| 页面 | 管什么 |
|---|---|
| **概览** | 直播数据、今天的量（点赞/收藏/评论/评论回复）、最近回复 |
| **直播互动** | 触发策略、发送配额、语音播报（音色可选可试听） |
| **评论区** | 评论区值班参数、立即扫一轮、最近回复记录 |
| **自动逛 B 站** | 分区/关键词、动作矩阵、最近动作、今日报告 |
| **人设** | 角色名、口头禅、风格、设定、别名 —— 点「预览效果」可用**没保存**的人设试说一句 |
| **设置** | 扫码登录、目标直播间房号、演练模式 |
| **日志** | 实时日志流 |

改完任何参数点右下角「保存设置」。机器人正在跑时保存会提示「重启后生效」，**不会打断当前直播**。

> 凭据存 `data/credentials.json`，**永不回显到页面**；演练模式只决策、不发送。

### 配置优先级

后台写的是 `data/settings.json` 和 `data/credentials.json`，**优先级高于 `.env`**。
扫码登录成功后，`.env` 里的三个 cookie 会被自动覆盖，不用再手动维护；
命令行 `scripts/run_live.py` 读的也是同一份，两条路不会打架。

## 四、评论区值班

主播的视频下面有人提问，AI 账号去接一句 —— 不依赖开播，风控也比直播低，是这套东西最稳的落点。

后台「评论区值班」卡片：

| 参数 | 默认 | 说明 |
|---|---|---|
| 服务器启动时自动开始值班 | 关 | 勾了才会自己跑，默认不偷偷动 |
| UP 主 UID | `0` | **填 0 自动从直播间房号推导**（省得再查一次） |
| 盯最近几个视频 | 5 | 只扫最新的这几个 |
| 扫描间隔 | 300 秒 | 太短容易吃风控，别低于 120 |
| 只回几小时内的 | 72 | **防止一上来把历史评论全回了** |
| 每天最多回几条 | 20 | 评论回复比弹幕更招人烦 |
| 两条最小间隔 | 90 秒 | |
| 评论字数上限 | 60 | 接口限制，超了发不出去 |
| 普通评论回复概率 | 0.5 | 提问、提到主播的**必回** |

点「立即扫一轮」可以不启动长驻任务，先看看会回什么。

### 它怎么筛

```
看过吗？ ──看过──> 跳过（rpid 落库，绝不重复回）
   │
   ├─ 自己的评论 ──> 跳过
   ├─ 楼中楼 ────> 跳过（只回顶层，不卷进骂战）
   ├─ 少于 3 字 / 纯表情 ──> 跳过
   ├─ 带链接、加群、私信、代练 ──> 跳过
   ├─ 超过时间窗 ──> 跳过
   └─ 提问 / 提到主播 / 抽中概率 ──> 交给 DeepSeek
```

一轮最多做 5 次模型判断，防止一次扫描烧太多 token。

### ⚠️ 一个必须知道的坑

**读评论也必须带凭据。** 不带 cookie 拉 UP 主视频列表，B 站会直接返回 `412` 风控页 ——
所以没扫码登录之前，这个功能连"看"都看不了。

遇到 `-412 / -352` 会自动退避 15 分钟，不要手动硬刷。

## 五、自动逛 B 站

它自己找视频、**读字幕原文**、判断值不值得看，再决定要不要留下痕迹。

### 怎么决定逛哪儿

| 你配的 | 它怎么找 |
|---|---|
| 只填关键词 | 按关键词搜，只搜 `BROWSE_DAYS` 天内 |
| 只选分区 | 取该分区的**周榜**（`RankType`，15 个分类可选） |
| 关键词 + 分区 | 先搜索，不够再补排行榜 |
| 都不填 | 不逛（会直接报错，不会瞎逛） |

> ⚠️ 搜索接口的 keyword **不能为空**，空串直接 `-400`。所以"只看分区"必须走排行榜。

### 动作矩阵：每样单独开关

| 动作 | 默认 | 风险 | 说明 |
|---|---|---|---|
| 点赞 | **开** | 低 | 看进去了就点，前先查 `has_liked` 防重复 |
| 收藏 | 关 | 中 | 收藏到你指定的收藏夹，不存在会自动建 |
| 投币 | 关 | **高** | **花账号真硬币**，除非要二刷否则别开 |
| 关注 | 关 | 中 | 改变账号关系，模型要给出理由 |
| 评论 | 关 | **高** | 只在真有话说时写，禁止"支持""不错"这类废话 |

每个动作三道上限：**开关** + **当日配额**（写库，重启不清零）+ **命中概率**。

### 成本阀门

`每轮最多读几条字幕` 是最烧钱的那个数字 —— 每条字幕要几千字进模型。
默认 `3`，每轮最多 3 次判断。嫌贵就调成 1，或者把间隔拉长。

### 报告

每轮都会往 `data/reports/browse-YYYY-MM-DD.md` 追加一条，后台「自动逛 B 站 → 今日报告」能直接看：

```markdown
- **01:27** [BV1YmnJ6eEKE](https://www.bilibili.com/video/BV1YmnJ6eEKE) 教妹妹开车，用我的声音
  - 来源 rank:Game · 播放 3736459 · 时长 2017s
  - 判断：真的玩下来了，妹妹那句"哥你嗓子是租来的吗"和最后车翻壳儿都挺有记忆点
  - 动作：like✅
```

判断理由必须具体 —— 提示词里明确写了"大部分视频应该被你划走"，不允许为凑数而 `worth=true`。

## 六、AI 账号的 Cookie 怎么拿

> 用 **AI 那个独立账号**登录，不是你自己的账号。搞错了就会变成"你回答你自己"。

1. 浏览器无痕窗口登录 **AI 账号**，打开 `bilibili.com`。
2. `F12` → **Application**（应用）→ 左侧 **Cookies** → `https://www.bilibili.com`。
3. 找到并复制这三个值：

| Cookie 名 | 用途 | 是否必填 |
|---|---|---|
| `SESSDATA` | 登录态 | ✅ 必填 |
| `bili_jct` | CSRF 校验，发弹幕必需 | ✅ 必填 |
| `buvid3` | 设备指纹，缺了风控概率显著升高 | ⚠️ 强烈建议 |

4. 贴进 `.env`，**不要带引号**（下面是形状示意，不是真值）：

```ini
BILI_SESSDATA=<原样粘贴，值里带 %2C 是正常的>
BILI_BILI_JCT=<32 位十六进制串>
BILI_BUVID3=<一串带 infoc 后缀的标识>
```

> 更省事的办法是走 **[Web 后台扫码](#三web-管理后台推荐)**，一条都不用填。

5. `python scripts/check_env.py` 应该打出 `AI 账号登录有效：xxx (uid=xxx)`。
   **一定要核对这里的名字**，确认是 AI 账号而不是你的大号。

> Cookie 有效期通常几周到几个月，过期后发弹幕会返回 `-101`，重新取一次即可。

## 七、让观众"听到" AI 说话

弹幕是文字，语音要进直播流，需要把音频送进 OBS。推荐 **VB-Audio Virtual Cable**（免费）：

1. 装 [VB-CABLE](https://vb-audio.com/Cable/)。
2. Windows 声音设置 → 输出设备改为 **CABLE Input**。
   （这样系统里所有声音都会进虚拟线，AI 的 TTS 自然也在里面）
3. OBS → 来源 → 添加 **音频输入采集** → 设备选 **CABLE Output**。
4. OBS 混音器里把这条拉低到 -18dB 左右，别盖过你的麦克风。
5. `.env` 里设 `SPEECH_BACKEND=play`。

**不想装虚拟声卡？** 保持 `SPEECH_BACKEND=file`，TTS 会落成 mp3 到 `data/speech/`。
你可以用 OBS 的**媒体源 + 热键**手动播放，或者干脆只发弹幕不发语音（`--no-speech`）。

> 注意：`play` 模式会把系统**所有**声音都送进直播（包括微信提示音）。介意的话用 [VB-Cable A+ B](https://vb-audio.com/Cable/) 建第二条线，或装 `sounddevice` 指定输出设备。

### 换音色

后台「语音播报 → 音色」是一个**可搜索下拉框**，点「▶ 试听」会当场合成一句念给你听，改完再保存。

- 中文音色 **14 个**（zh-CN 6 + 方言 2 + 港台 6），总音色 322 个
- 下拉里选，也可以直接粘任意 voice ID（比如英文的 `en-US-AriaNeural`）
- 音调 `TTS_PITCH` 能再拧一道：`+50Hz` 更活泼，`-50Hz` 更低沉

几个常用的：

| voice ID | 性别 | 听感 |
|---|---|---|
| `zh-CN-XiaoxiaoNeural` | 女 | 自然、亲和，默认值 |
| `zh-CN-XiaoyiNeural` | 女 | 更年轻、偏软 |
| `zh-CN-YunxiNeural` | 男 | 少年感，适合傲娇/嘴贫 |
| `zh-CN-YunjianNeural` | 男 | 沉稳播音腔 |
| `zh-CN-liaoning-XiaobeiNeural` | 女 | 东北话，整活效果强 |
| `zh-CN-shaanxi-XiaoniNeural` | 女 | 陕西话 |

> ⚠️ **edge-tts 必须 ≥ 7.3.1**。老版本会被微软挡成 `403 WebSocket handshake`，
> 表现为「试听失败 / 语音播报失败」。升级：`pip install -U "edge-tts>=7.3.1"`。

> edge-tts 是「语音合成」，不是「声音克隆」。想要**你自己的声音**得换引擎
> （GPT-SoVITS / CosyVoice / Fish Audio 这类），那要单独跑一个推理服务，改动不小。

## 八、调参：安全第一

`.env` 里最该动的是这四个数，它们决定账号能活多久：

```ini
SEND_MIN_INTERVAL=12    # 两条弹幕最小间隔（秒）
SEND_PER_MINUTE=3       # 每分钟上限
SEND_PER_HOUR=25        # 每小时上限
SEND_PER_DAY=180        # 每天硬上限（写入数据库，重启不清零）
```

**新手建议从更保守的值起步**：`SEND_MIN_INTERVAL=20`、`SEND_PER_HOUR=15`、`SEND_PER_DAY=100`。
跑几天没问题再慢慢松。

刻意调低触发概率，宁可不说话：

```ini
REPLY_PROBABILITY=0.12   # 普通闲聊被抽中的概率
```

### 挑弹幕的逻辑（`biliauto/live/guard.py`）

| 消息类型 | 处理 |
|---|---|
| SC / 上舰 | 最高优先，必回 |
| 叫 AI 名字 / @它 | 高优先，必回 |
| 带问号 | 高优先，必回 |
| 纯数字、纯叠字、刷屏 | 直接丢弃 |
| 其余闲聊 | 按 `REPLY_PROBABILITY` 抽样 |

另外有两条保护：**同一人 4 分钟内只回一次**；**超过 30 秒的弹幕不再回**（晚回比不回更怪）。

## 九、风控与合规（请认真读）

这套系统最大的风险不是代码 bug，是**账号被限流或封禁**，以及**内容出事**。

**降低账号风险：**

- AI 账号先养几天：绑手机、实名、看直播、发几条正常弹幕。零等级新号发弹幕几乎必被限。
- 一开始每天别超过 50 条，观察有没有"发送成功但别人看不见"（影子限流）。
- 不要在同一直播间高频刷相似句式。配额的 `USER_COOLDOWN` 就是防这个的。
- 出现 `-412`（风控）立刻停，隔几小时再试，别硬刚。

**降低内容风险：**

- 系统提示词里已经禁了政治、色情、赌博、医疗/投资建议，但**模型不是保险箱**，仍可能说错话。
- 建议先跑一周 `--dry-run` 或只发语音不发弹幕，人工抽查日志。
- 直播是公开场合，AI 说的每句话都算在你账号头上。

**合规提示：**

- B 站对 AIGC 内容有标识要求。建议在 AI 账号简介里注明"本账号由 AI 参与互动"。
- 不要用这个系统冒充真人身份做背书、带货、引流。
- 平台规则会变，接口挂了要接受"改代码"这件事。

## 十、排错

| 现象 | 原因 | 处理 |
|---|---|---|
| `-101` | cookie 过期 | 重新取 SESSDATA / bili_jct |
| `-412` / `-352` | 触发风控 | 停 4 小时以上，降低频率 |
| `10030` 或发送失败 | 弹幕超长 | 系统已自动截断到 `MAX_DANMAKU_LEN`，调小它 |
| 收不到弹幕 | 房间没开播 / 房号错 | `check_env.py` 看直播状态 |
| 弹幕发了但观众看不见 | 影子限流 | 换号或停一段时间 |
| 语音听不到 | OBS 没采到 CABLE Output | 检查 OBS 音频输入设备 |
| DeepSeek 报 401 | key 错 | 检查 `DEEPSEEK_API_KEY` |

日志默认打在控制台；要留档就重定向：

```powershell
python scripts/run_live.py *>> logs\run.log
```

## 十一、代码结构

```
biliauto/
  config.py          .env 解析 + 校验 + settings.json 合并（唯一读环境变量的地方）
  llm.py             DeepSeek 调用、JSON 容错、系统提示词
  auth/
    qrlogin.py       B 站扫码登录（passport 二维码流程）
    vault.py         credentials.json / settings.json 读写
  web/
    app.py           FastAPI：状态、设置、启停、日志、登录
    static/          单页后台（侧边栏七页，原生 JS，无构建步骤）
  bili/
    credential.py    凭据构建 + 登录态自检（归一化成 AccountInfo）
    danmaku.py       直播间事件流解析（抗脏数据）
    actions.py       发弹幕（唯一有副作用的出口）+ TTS
  comments/
    collector.py     拉 UP 视频与评论（带凭据，否则 412）
    duty.py          评论区值班：去重、筛选、配额、退避
  browse/
    source.py        候选来源：关键词搜索 / 分区周榜 / 热门
    actions.py       动作执行器：点赞/收藏/投币/关注（查 has_* 防重复）
    runner.py        巡视循环：读字幕 → 判断 → 执行 → 写报告
  live/
    guard.py         触发策略 + 配额（系统的"刹车"）
    bot.py           主控：队列、上下文、记忆、生命周期
  memory/
    store.py         SQLite：事件、回复、观众画像、已处理评论、每日用量
scripts/
  run_web.py         Web 后台入口（推荐）
  run_live.py        命令行开播入口
  check_env.py       环境自检
  replay.py          离线回放（不连 B 站）
tests/
  test_core.py       69 项断言，python tests/test_core.py
```

**改动建议**：想改性格就只动 `llm.py` 里的 `build_system_prompt`（或直接用后台的人设表单）；
想改"什么时候说话"就只动 `guard.py`。这两个文件覆盖了 90% 的调优需求。

## 十二、下一步能加什么

按性价比排序：

1. **评论区值班**：视频发布后自动回评论（`bilibili_api.comment`，接口成熟、风控比直播低）。
2. **下播复盘**：把 `data/biliauto.db` 的日志喂给 DeepSeek，生成"今晚哪些梗接得好"。
3. **动态运营**：定时发动态、转发二创（`bilibili_api.dynamic`）。
4. **自动投稿**：`video_uploader` 可上传，但需要素材生成 + 封面 + 标签 + 分区一条龙，且风控最重，建议最后做。
5. **弹幕点歌 / 点播**：把弹幕指令映射到本地动作，比纯聊天更有直播价值。
